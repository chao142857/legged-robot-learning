# nSGS-CL1：多学生闭环基座与退化情境微调
## 给 Codex 的执行协议

本文件是下一轮实验设计，不是已经启动或完成的运行记录。
当前 CleanMeta8、Uniform、Fresh 结果保持原样。本实验独立建分支、目录和结果谱系。

## 0. 目标与执行范围

训练一个共享的、小型有记忆 Teacher，根据不同 Student 的实时学习状态和近期变化，每 100 次学生 PPO 更新调整一次任务分布。
第一阶段学习一般教学能力；第二阶段在退化与正常情境混合的真实续训中微调。同一个网络贯穿两个阶段。
本轮首先在 YangLab 单卡推进；不要求两套 Isaac Sim 同时常驻显存，不占用 Ubuntu 上其他任务。
不得把本文件当作远端空闲凭据：启动前检查实际进程、GPU、队列及占用，不终止无关作业。

仅要求实现正确、能够完成真实教学闭环的工程验收，不把离线统计显著性设为正式训练准入。
本轮不实现 WM、参数加噪生成 Student、硬聚类、TV 半径搜索或大规模 checkpoint 三分叉。

- 两个源 Student 暂定 seed43、44，各自从零初始化、独立训练至 10k。它们是元训练源，不是未见测试学生。

## 2. Student 与 Teacher 的分工

Student：
- WBC 原生 PPO，4096 env，rollout=24；每个源学生有自己的 actor、critic、Adam、归一化、环境/RNG、命令游标、采样反馈和当前 update。
- 不将两个源 Student 的模型参数、优化器或任务历史平均。

Teacher：
- 一个共享的状态编码器 + 单层 GRU（hidden size 64）+ 八维 Gaussian 偏好策略头 + 标量 value head。
- 源学生各自保存 Teacher 原始输入/动作/收益历史及隐状态；不能串用学生A的记忆给学生B。
- 不输入 seed ID、未来表现、正式测试指标或“将来会退化”的标签。
- 全局输入包括当前开发表现、EE/Loco连续指标、近期差分、上一段偏好和反馈，以及数据年龄/证据量摘要。
- 逐序列近期误差、进度、年龄、证据量、缺失标记继续作为现有序列打分解码器的输入。
- 保留修复版 V0.2 已定义的八维偏好到32768条序列概率的解码关系；先检查特征顺序、符号、归一化一致，不重新发明八种手写课程。
- 初始 mean head 输出接近零，使用20% Uniform mixing。元训练通过低维偏好动作探索，不通过给 Student 权重加噪扩增。
- 一个宏动作对应一个100-update区间。先用期初输入快照生成 q，并在这个区间内固定 q；真实反馈持续记录，下一宏步再刷新。
- 每次记录原始偏好动作、实际解码动作、行为策略 log_prob/value、q、Teacher版本及状态快照。若含 tanh/裁剪，明确概率定义；不能用裁剪后的值冒充未裁剪 Gaussian 样本的 log_prob。
- Teacher PPO 的动作是八维偏好，不是本段数千次 sequence_id 抽样。后者仍保存用于审计，不复制为数千个独立教师奖励。

建议首轮外层工程初值：
- encoder hidden=64，GRU hidden=64；
- Gaussian std 初值0.2，具体参数化与是否学习std在 manifest 锁定；测试时执行均值偏好；
- Adam lr=1e-4，clip=0.2，gamma=0.99，GAE lambda=0.95；
- value_coef=0.5，entropy_coef=0，max_grad_norm=0.5，epochs=2；
- 连续整段序列训练，绝不把不同时刻和学生的RNN状态当独立样本乱序；
- 使用Teacher行为策略的实际KL监控/提前停止，初值target_kl=0.01；这是外层PPO，不复用旧多候选Adam回溯器。
这些数是预先指定的首轮配置，不是经验验证的最优值；不能中途按测试成绩搜索。

## 3. 阶段A：单卡交替推进两个真实学生

一个宏动作 = 100次Student PPO更新。
每个源学生收集5个连续宏步（500次Student PPO），然后在同一个Teacher版本下收集另一学生的5个宏步。
两份轨迹齐备后，合计10个教师转移，进行一次外层Teacher PPO更新。

示例：
Teacher v0：
  Student43 0->500（5次教学决策）
  Student44 0->500（5次教学决策）
  汇总 -> 更新Teacher v1
Teacher v1：
  Student43 500->1000
  Student44 500->1000
  汇总 -> 更新Teacher v2
……
直到两个学生均完成10k。

- 采集一批期间冻结Teacher参数；不能先用A更新Teacher，再把旧策略采集的B数据冒充同批on-policy数据。
- 每个学生的GAE/return单独计算；500边界是rollout截断而非学习任务终止，应按规定bootstrap；真正10k结束才按本实验终止定义处理。
- Teacher PPO保存旧log_prob和value；训练时按连续片段计算新分布。
- Teacher权重更新后，根据每个学生已观测到的真实历史，在新参数下重建相应GRU隐状态（no_grad前缀回放/burn-in）；不可把旧参数产生的hidden默认为新参数下完全一致。
- 中间切换Student、保存恢复或进入开发评测时不能误清空Teacher记忆；全新Student或新微调片段才有明确的初始化/burn-in规则。
- 实验输入预处理与统计来源固定，不能借用测试集拟合尺度。

单卡运行：
- 优先采用一个常驻仿真实例与两个独立学生存档，在500边界切换；模型和轻量状态可在CPU驻留。
- 复用已核验的恢复流程，记录所有可保存物理/环境/命令/指标状态。不要声称PhysX接触缓存可逐位恢复。
- 如无法恢复进行中回合，统一执行显式边界reset；未完成回合单独标记为boundary_interruption，既不能虚构成功，也不能当自然失败。记录实际曝光和边界丢失，未来对照使用同一切换规则。
- 不要求为实现双学生而默认同时开两套4096-env仿真。若显存或恢复有硬阻碍，先完成可用工程工作并报告具体阻碍，不擅自减env、换任务或改学生预算。

预算：
- Student更新：2×10k=20,000。
- 教师真实决策：2×100=200个。
- 外层采集/更新批次：20个，每批10个转移（每次可有预定2个优化epoch，不算新增经验）。
- 训练环境转移：1,966,080,000，开发/正式评测另计。
- 这是首轮可行性预算，不是大量教师数据，不能用学生环境步数冒充教师样本数。

## 4. Teacher反馈与评测隔离

- 主要Teacher指标 J 沿用当前干净版本的开发集连续联合达标得分定义。
- 宏步奖励 r_k = J_{k+1} - J_k。reward-to-go/GAE包含后续真实宏步收益及截断处value，不只用即时奖励乘log_prob。
- Teacher value不能通过最终测试集拟合；不把Student训练回报代替固定开发分布上的收益。
- 在声明的gamma下使用上述差分奖励。它并不直接等价于最小回撤目标；首轮将回撤/恢复作为独立报告指标，不能声称所有短期下降均应消除。
- 开发面板沿用256条×2次固定重置及均值动作口径，每100 Student updates评测；初始J也实际测量。
- 开发评测不写入训练序列历史、不改变Student训练RNG或强行清空训练回合。
- 主要报告四项物理误差、连续联合达标、严格5cm/80%成功率、原生失败，聚合分母严格固定。
- 正式测试池不进入教师输入、奖励、状态重建、梯度或参数选择。
- 源学生按原频率可生成正式评测用于完整记录，但不得据其结果改训练日程。
- 在固定新学生测试时Teacher参数冻结，GRU记忆和输出仍随真实开发/训练历史变化；不能把“冻结权重”实现成“冻结采样表”。

## 5. 阶段B：退化情境微调，上限4k学生updates

Base训练完成，锁定并保留Base Teacher、优化器、源码、配置和全部源学生历史。
第二阶段继承同一网络及优化器，不改学生奖励、Teacher开发目标或采样解码关系。

构建8个练习片段：4个退化情境+4个正常情境，两个源seed尽量均衡；每片段真实续训500次。
- 使用源训练开发/训练历史，不按正式测试曲线挑选。
- 初版只研究已经出现可观测下降后的恢复/保持，不宣传提前预警。
- 选集规则在读取未来测试结果前固定。建议退化标志：最近两次J均值比之前三次均值低≥0.03，且相同窗口的EE位置RMSE高≥0.003m；阈值只是候选片段选取规则，不作为Teacher手写控制策略。
- 起点信息仅来自该时刻及以前；Teacher看不到未来退化深度或“这条是恢复成功案例”的标签。
- 正常片段从相近训练阶段、足够早以能续训500的其他源状态中按预置随机规则选取；不要挑最终收益最大者。
- 同一退化事件避免重复计为多个独立片段。
- 优先使用源43/44的完整新快照。若真实片段不足，报告实际覆盖与可用预算；不伪造事件、不偷偷增加完整学生训练。可以提出复用已有干净Uniform/Fresh源学生起点，但必须完整核验并单列来源。
- 片段不是模仿学习标签：从完整Student状态恢复，由当前Teacher重新收集真实动作和后续回报。
- 利用起点之前的原始历史重建Teacher记忆；旧历史只做上下文/burn-in，不重新当作当前on-policy actor训练样本。
- 一批含两个源seed、退化/正常各半的4个片段，固定同一Teacher版本收集，之后统一更新；两批共8段。
- 每段5个教师宏步，共40个新教师转移。片段500步终点按“本练习有限时域”结束，明确记录return的终止语义。
- 完成后保存Base与Recovery两个独立Teacher，不覆盖Base。
- 正常片段不是可省略项；本轮不只训练“救火”，也不把始终低性能但不回退算作成功。

## 6. 工程验收：通过后执行，不要求先涨点

必须检查：
1. 修复运行时实际加载；CPU快照、Adam拒绝/异常/恢复行为有回归测试。
2. 两个学生之间模型、RNG、反馈、GRU状态完全隔离；单卡轮换后身份正确。
3. 一批Teacher数据只来自该批冻结行为策略；log_prob、Gaussian动作和真实q对应。
4. 单个宏动作贡献一次Teacher转移，不能复制成数千条虚假样本。
5. RNN序列mask、burn-in、rollout截断bootstrap与真正终止正确。
6. Teacher参数固定时，真实学习历史变化能够进入hidden和输出；没有状态变化时仅恢复不应改输出。
7. 开发/正式测试隔离，失败及计分分母与既有协议一致。
8. 独立smoke至少覆盖A/B各两个宏步、一次外层更新、一次隐状态重建及保存恢复；smoke的Student/Teacher不能直接冒充正式从零起点。
9. 报告教师梯度、更新KL、clip比例、value拟合、q的TV和实际曝光，不把非零梯度或更大TV当作性能验收。

正式源训练不因中途单点涨跌停止、改seed或调参数。
必要工程异常可以停止并报告；不自动启动额外10k支线或新学生测试。

## 参考方法依据与边界

- RL²（https://arxiv.org/abs/1611.02779）：网络权重与运行期记忆的两层适应思想。
- Recurrent PPO官方文档（https://sb3-contrib.readthedocs.io/en/master/modules/ppo_recurrent.html）：说明时序策略训练及隐藏状态/episode-start的重要性；该官方实现是LSTM，本设计使用GRU，不能宣称直接无修改复用。
- PPO说明（https://spinningup.openai.com/en/latest/algorithms/ppo.html）：on-policy采集、旧log-prob、优势估计与KL提前停止。
